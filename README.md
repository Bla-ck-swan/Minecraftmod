# 一：ElytraSlot

## 核心功能：
在副手位置上方加入一个自定义槽，只能存放鞘翅，并禁用胸甲槽可以存放鞘翅的功能，达到可以同时在身上穿戴胸甲与鞘翅的目的。并且鞘翅飞行判定，飞行粒子/音效，鞘翅模型渲染，耐久消耗，附魔效果，物品/装备交互，数据同步，持久化（存档）等均走原版逻辑，兼容性较强。

## 已知问题：
1.游戏内（特别是多人模式）图像渲染有时会出问题

2.在（多人游戏，服务器）游戏规则内keepInventory=true时死亡后不复活直接退出并且服务器端重启会丢失鞘翅槽的物品

这些bug都不影响游戏体验甚至很难触发，目前修复成本大于收益，暂不修复

## 使用方式：
单人存档直接拖入mods文件夹，多人模式（服务器）要正常使用需要双端（服务器，客户端）下载，双端共用一个jar文件即可

## jar产物位置：
product/elytraslot-x.x.x.jar

## 适用版本：

|--------|--------|
|1.0.0|26.2-fabric|


# 二：NetworkOp

## 核心功能：
压缩原版区块数据包达到节省CPU资源并节省宽带的目的。测试证明，在zstd level3（默认配置），N=10的情况下压缩相同体量的数据包对于CPU的资源占用降为原版zlid压缩的1/15资源，压缩相同体量的任务产生的数据包比原版zlid压缩产生的数据包小10%左右，例如原版zlid压缩后需要的传输量为1MB，模组传输仅需要0.9MB。N=mix(player view distance,server view distance)

## 原理：
服务器端：不再逐个压缩各个区块的数据包并传输，而是拦截区块数据包直到总量达到N，然后集体zstd压缩这N个区块包合成一个压缩包，最后传输给客户端

客户端：如果服务器没有开启zstd压缩则走原版途径，如果服务器开启zstd，客户端也默认开启模组传输接口，完成zstd解压后交回原版处理

双端部署模组后服务器端在zstd=true时 VarInt 编码从3字节开放到4字节，理论最大帧从2MB扩大到268MB，用于应对N值巨大且重复量小时产生的巨大帧，客户端始终开放4字节 VarInt 编码应对来自服务器的大帧

注：事实上N越大，压缩率越好看，N越小，原本要传的数据也少，另外也不用担心因为拦截区块包导致客户端视角出现空洞，如果N的值小，N个区块包攒的快，当N的值大，被拦截的区块包都在远处，都不影响游戏体验

## 已知问题：
重构了部分Netty IO线程逻辑，可能与Krypton等网络优化模组不兼容

## 使用方式：
需要双端（服务器，客户端）下载，双端共用一个jar文件即可，双端尽量部署同一个版本的模组
如果服务器不开启zstd压缩，客户端有没有模组都可以正常运行，但如果服务器开启了zstd压缩，那客户端必须也有这个模组
在服务器开启如果没有配置文件会自动生成配置文件

## 配置文件：
| 选项 | 默认值 | 功能 |
|------|--------|------|
| zstd | false | zstd 压缩开关，1.0.0 版本及以上开启会禁用原版 zlib 压缩 |
| debug | false | 调试模式，开启后会在服务器打印压缩率 |
| batch | 8 | 当无法获取 player view distance 和 server view distance 时，N 等于这个值 |
| zstdLevel | 3 | zstd 压缩级别 |
